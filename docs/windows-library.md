# Библиотека Windows-игр

Экран `/games` открывает дизайнерский экран из `public/prototype` (`games.js`, коммит `059b12b` ветки `ui/storage-collection-prototype`). Без `?demo=1` список игр берётся один раз из `GET /api/windows-library`. Демо-карточки в этот список не попадают. Перенос в «Играю сейчас» и возврат в архив спрашивают подтверждение и только потом ставят задание. `diskutil` и таймер опроса диска этот экран не запускает.

## Индекс

Том приходит событием, не опросом.

- Windows NTFS: одно чтение MFT на том (`read-mft`). Дальше `FSCTL_QUERY_USN_JOURNAL` (`0x900F4`) и `FSCTL_READ_USN_JOURNAL` (`0x900BB`). Повторное MFT отклоняется.
- Журнал потерян, если сменился `UsnJournalID` или `LowestValidUsn` ушёл дальше сохранённого курсора. Тогда один обход, MFT заново не читается. Запись USN без известного родителя не получает выдуманный путь.
- exFAT и FAT: один обход при подключении. Второй раз обход не принимается.
- `E:`, `Z:` и виртуальный `F:` не индексируются.
- Mac, если событие всё же пришло: `diskutil info` один раз на новый том, дальше FSEvents. Полный обход только при первом подключении или дыре в `lastEventId`. Повторный `diskutil` не запрашивается.

`POST` с `action: "advance"` отвечает отказом. Копирование в пул и снятие с пула не идут отдельной очередью библиотеки: экран вызывает ту же подготовку, что и `game prepare` / `game remove`. Задание пишется в общую `jobs.json`. Один проход `dispatchOnce` его забирает: копия, SHA-256, затем `compact.exe` всего корня копии на NTFS. База CompactGUI пропускает почти несжимаемые игры. На Linux `compact.exe` не запускается и сжатие не засчитывается. Холодная копия на HDD не удаляется. Снять игру с пула можно только явным `return`, и только если холодная копия всё ещё совпадает с проверенным манифестом. Выход из игры и нехватка места никого из пула не вытесняют.

## Очередь

Отдельного задания «сжать потом» нет. Файл `database.json` в репозиторий не кладётся. Неизвестная экономия не считается нулём и не ставит игру готовой.

«Играю сейчас» и снятие с пула требуют `confirm: true` и список процессов. Процесс внутри корня — отказ, файлы не меняются. `E:`, `Z:` и виртуальный `F:` в этот путь не открываются. Чужое назначение без метки этой копии не перезаписывается.

Быстрый SSD задаётся настройкой `serial`, `uuid`, `root`. Путь в коде не выбран.

Обложка: кэш, иначе адрес CDN Steam по AppID, иначе имя. SteamGridDB только как ключ кэша. Запрос списка ничего не скачивает. Ключ пользователя не требуется и в код не записан.
