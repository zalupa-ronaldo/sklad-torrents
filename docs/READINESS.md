# Что реально подключено

Один процесс `service start` читает общую `jobs.json` и сам доводит снимок, подготовку игры, HandBrake и завершённую локальную раздачу. CLI и страница прогресса смотрят туда же. `work` и `game work` остаются отладкой.

Проверено на Linux-фикстурах и локальном протоколе, не на живых дисках:

- копия игры сверяется хэшами, повтор и рестарт службы не плодят задание;
- низкая экономия базы пропускает запуск без сжатия, неизвестная экономия остаётся `unknown`;
- `compact.exe` на Linux не запускается, физический NTFS не проверялся;
- крошечный AV1 доходит до `verified`;
- завершение раздачи ставит одну копию, дата `completion_on` не сдвигается, ratio 3 или 72 часа открывают порог, исходник при равном размере копии не удаляется;
- E: и Z: отсекаются до чтения пути.

Продакшен по-прежнему закрыт: пути пула, staging и запас не заданы. Старую чистую базу и резервы сюда не переносить наугад. Живой qBittorrent не проверялся.

Нативный smoke `65ce17f` на отдельных тестовых каталогах, не на живом Складе, уже был. Этот коммит его не повторяет и успехом всего продукта не считает.

- Windows `compact.exe` реально сжал свой корень `game-efe22bfd6b02`: logical 1048576, stored 36864, SHA копии и источника `4e29ad18ab9f42d7c233500771a39d7c852b200baf328fd00fbbe3fecea1eb56`. Игра осталась `blocked`, `compressed: false`, причина «allocated и WOF неизвестны». Код выхода 0 успехом не был. Теперь Windows читает только файлы этого корня через `GetCompressedFileSizeW` и `compact /Q`. Совпадение обоих чисел и меньший allocated дают `compressed: true` и запуск. Неизвестное остаётся null. Linux-прогон это измерение не выполняет.
- Windows `encode --hardware-only` остановился до HandBrake: `ffprobe не найден`. Рядом уже лежит проверенный ffprobe 9.0.2 x64 Gyan, `ffprobe.exe` SHA256 `f0d36ecbbdd3bcfac3efa078c96c7271c2e68b3810595552ac3b7f17e9a65c52`, архив `60f467265b1e312373dbcd92200c2618a74850f98d3d078e94296bb3fa2047ba`. Путь: `C:\Users\user\.local\sklad-test-20261108-smoke-9d44065e\tools\ffmpeg-release-essentials\package\ffmpeg-9.0.2-essentials_build\bin\ffprobe.exe`, `ffmpeg.exe` в том же каталоге. Код ищет `SKLAD_FFPROBE`, `SKLAD_FFMPEG`, `--ffprobe` и `--ffmpeg`. Сам путь в программу не зашит. Windows не объявляется неподдерживаемой. Проверка по коду выхода HandBrake не подменяется.
- Прямой `vce_av1` HandBrake 1.11.1, не argv Склада: ролик 160x120, CQ 30, mux mkv, stdout пустой, последняя строка `encavcodecInit: AV1 (AMD VCE)`, код 3221225477. Исходник не изменился. В логе нет кода ошибки AMF и нет подмены на HEVC или svt_av1. Документация HandBrake говорит, что AV1 Navi 3.x хочет ширину и высоту, кратные 64. 160 и 120 не кратны 64, а 9070 XT в этой фразе не назван. Причина access violation этим не установлена. Драйвер отсюда не предлагается. `vce_av1` из справки остаётся заблокированным, автоповтор выключен. Один отдельный retest ниже, не цикл.
- Mac software AV1 прошёл: источник 64229 байт, выход 33478, длительность 2.005333, AV1/AAC, исходник на месте. Файл `pipeline-av1.mkv` при этом был MP4, потому что argv всегда ставил `av_mp4`, а проверка принимала оба контейнера. Теперь `.mkv` требует `av_mkv` и формат matroska, `.mp4` требует MP4. Несовпадение не становится успехом. Звук и субтитры из argv не убраны.
- Задания на Mac были помечены `linux-local`. Теперь хост берётся из платформы процесса: Mac `mac-local`, Windows `pc-agent`, Linux `linux-local`. Чужой хост в ответе probe — `unconfigured`, не «этот процесс Linux».

## Повтор изолированного smoke после этого коммита, отсюда не запускать

Старые тестовые каталоги не переиспользовать как живой Склад. Новый пустой `SKLAD_DATA_DIR` на каждой машине. E:, Z:, F:, игры, медиа, MFT и службы не указывать. Firewall не менять.

Windows, в окружении процесса, не в git:

```bat
set SKLAD_FFPROBE=C:\Users\user\.local\sklad-test-20261108-smoke-9d44065e\tools\ffmpeg-release-essentials\package\ffmpeg-9.0.2-essentials_build\bin\ffprobe.exe
set SKLAD_FFMPEG=C:\Users\user\.local\sklad-test-20261108-smoke-9d44065e\tools\ffmpeg-release-essentials\package\ffmpeg-9.0.2-essentials_build\bin\ffmpeg.exe
```

Тот же путь принимают `--ffprobe` и `--ffmpeg` у одной команды `encode`. Служба видит только переменные окружения своего процесса. Сначала `encode probe` и убедиться, что `ffprobe` не `missing`, `localHost` равен `pc-agent`, `hardwareAv1` равен false, а `hardwareBlock` называет код 3221225477. Затем один новый eligible-корень в пустом пуле: после `service start` у копии `ready: true` только если `logicalBytes`, `allocatedBytes` и `wofBytes` числа и allocated меньше logical. Равный размер остаётся `compressed: false` и не запускается. Неизвестный размер остаётся null.

Один раз, не циклом, отдельный клип с шириной и высотой, кратными 64, например 256x128, тем же прямым вызовом `vce_av1`, CQ 30, mux mkv. Это проверка опубликованного ограничения Navi 3.x, не найденная причина падения и не смена драйвера. Если код снова 3221225477, кодировщик остаётся blocked. Программный AV1 — отдельная команда без `--hardware-only`.

Mac: один новый ролик в `dest` с суффиксом `.mkv`. В журнале `container` равен `mkv`, `format` содержит matroska, `host` равен `mac-local`. Файл с байтами MP4 при имени `.mkv` успехом не считается. Исходник остаётся.

Локальный loopback-координатор есть. Это не доказательство ПК или Mac и не включённый LAN. На этой VM три отдельных процесса (координатор и два воркера) с тремя каталогами данных прогнали два разных крошечных ролика через HTTP на `127.0.0.1`. Очередь `jobs.json` лежит только у координатора. Оба воркера реально вызвали HandBrakeCLI 1.7.2, интервалы пересеклись на 1503 мс, выходы 10701 и 10701 байт, кодек AV1, sha256 выходов разные, исходники остались. Повторная сдача без lease получила 409 и размер выхода не изменился. Без токена ответ 401. Чужой путь и `../` дают 404. Битый хэш куска не пишется. Повтор смещения отклоняется. Протухший lease не сдаёт результат и не плодит второе задание. Рестарт хаба оставляет одну запись. Обрыв воркера не ставит verified и не удаляет исходник. Воркер только с `x264` не получает AV1. `E:\` и `Z:\` отсекаются до открытия. Имена 1.11.1 (`vce_av1` в справке, отсутствие `vt_av1`) не считаются рабочим аппаратным прогоном и не подменяют AV1 на HEVC.

Слушать не-loopback адрес код отказывается, пока нет `SKLAD_ENCODE_ALLOW_LAN=1` и явного `--bind`. По умолчанию адрес `127.0.0.1`. Токен берётся из `SKLAD_WORKER_TOKEN` и в git, `hub.json`, журнал воркера и stdout не пишется. Отдельного TLS нет и здесь не придумывается: пара — общий секрет и сравнение без утечки по времени. Для чужой сети этого мало. Firewall и антивирус эта команда не трогает. Воркер не получает путь исходника координатора и не может его удалить. Снять исходник может только координатор, и только после commit и уже существующей политики.

## Как позже явно включить LAN, это ещё не сделано

1. Выбрать адрес сам, не оставлять значение по умолчанию.
2. Поднять хаб с `--bind <этот адрес>` и `SKLAD_ENCODE_ALLOW_LAN=1`.
3. Передать воркерам тот же `SKLAD_WORKER_TOKEN` и `SKLAD_HUB` вне репозитория, не через чат и не через файл в git.
4. Считать сеть доверенной только своим решением. Пока нет отдельного TLS, открывать хаб в чужой сети нельзя.
5. На каждой машине задать `SKLAD_HANDBRAKE` на уже установленный `HandBrakeCLI` 1.11.1. PATH и службу не менять этой командой.

## Изолированная проверка на ПК или Mac, не запускать отсюда

1. Три пустых каталога: координатор, воркер ПК, воркер Mac. У каждого свой `SKLAD_DATA_DIR`. Общий `jobs.json` не подкладывать.
2. Текущий `data/` скопировать в архив рядом и этой командой не открывать.
3. Не указывать E:, Z:, игровые папки, раздачи и пользовательское видео. Не снимать firewall и антивирус.
4. Сначала только `127.0.0.1` на той же машине, с временным токеном в переменной окружения. `SKLAD_HANDBRAKE` указывает на локальный 1.11.1, но файл для прогона — один сгенерированный ролик, не библиотека.
5. Поднять `encode hub`, затем `encode worker --id <имя> --role pc|mac`. Убедиться, что выход verified, исходник на месте, в каталоге воркера нет `jobs.json`.
6. Остановить процессы. Сверить, что пользовательские каталоги не изменились.
7. LAN из раздела выше не включать, пока шаги 1–6 на пустых каталогах не пройдены отдельно на ПК и отдельно на Mac. Этот облачный прогон их не заменяет.
