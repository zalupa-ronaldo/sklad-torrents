# Склад

Локальная панель. qBittorrent ставится отдельно, своего торрент-движка здесь нет. Без настоящего железа работают демо-хосты и mock-исполнители. В этом облаке диски не записывались, настоящая MFT не читалась, передача LocalSend до реального компьютера не доводилась.

Панель закрывает qBittorrent на Mac mini и Windows, полку дисков, очередь заданий, правила контента, HandBrake и сжатие NTFS. Что входит в продукт и какие противоречия уже сняты — в [docs/PRODUCT_SPEC.md](docs/PRODUCT_SPEC.md).

Прокси и VLESS не нужны. Панель ходит в Web UI qBittorrent и в агентов напрямую по домашней сети.

## Запуск

Нужен Node.js 22. Команды ниже — из корня репозитория, где лежит `package.json`.

```bash
npm install
npm test
npm run dev
```

Панель: [http://127.0.0.1:4317](http://127.0.0.1:4317).

`npm test` поднимает поддельный Web API qBittorrent в процессе. Настоящий Mac или ПК для тестов не нужен.

Сразу видны два демо-хоста, «Mac mini» и «Windows PC», с несколькими раздачами. Они не выходят в сеть. Добавление магнет-ссылки на демо-хосте меняет список в этом процессе; перезапуск `npm run dev` возвращает исходные демо-раздачи. Настоящие хосты и отметки «к переносу» пишутся в `data/` и переживают перезапуск.

## Настоящие агенты хостов

Полка в демо, пока режим не `agents`. Это решает `src/addons/drives/store.ts`. `SKLAD_DRIVE_MODE=agents` включает агентов, `SKLAD_DRIVE_MODE=mock` возвращает демо. Если переменная не задана, берётся `"mode"` из `data/drive-agents.json`, а когда файла нет — снова `mock`. Адреса, которые панель подставляет, когда в этом файле нет списка агентов:

- Mac: `SKLAD_MAC_AGENT_URL`, иначе `http://127.0.0.1:4371`
- Windows: `SKLAD_WINDOWS_AGENT_URL`, иначе `http://127.0.0.1:4372`

Оба процесса полки слушают `0.0.0.0` на своём порту. Макет включается только флагом `--mock` (`process.argv`). Переменной `SKLAD_PC_AGENT_MOCK` эти два файла не смотрят. Чтобы читать эту машину, `--mock` не передают.

### Mac

Рабочий каталог — корень этого репозитория.

```bash
node --import ./agents/register.mjs agents/mac-agent/drive.mts --port 4371
```

Файл: `agents/mac-agent/drive.mts`. Если `--port` не указан, код всё равно берёт `4371`. Сбор томов в `agents/mac-agent/collect.mts` вызывает `diskutil info -all` только при `process.platform === "darwin"`. На другой системе агент отвечает, что сборщик macOS запущен не на Mac, и список томов пустой.

Панель на этом же Mac, из того же корня:

```bash
SKLAD_DRIVE_MODE=agents SKLAD_MAC_AGENT_URL=http://127.0.0.1:4371 npm run dev
```

Адрес, который должна использовать панель: `http://127.0.0.1:4371`.

### Windows

Тот же корень репозитория. Сборщик `agents/pc-agent/collect.mts` работает только при `process.platform === "win32"` и вызывает `powershell.exe`. Процесс `node` внутри Linux-дистрибутива WSL — это Linux: тома не читаются, ответ «Сборщик Windows запущен не на Windows.» Запускайте Windows-сборку Node (cmd или PowerShell на Windows), не `node` из WSL.

```bash
node --import ./agents/register.mjs agents/pc-agent/drive.mts --port 4372
```

Файл: `agents/pc-agent/drive.mts`. Порт по умолчанию в коде — `4372`.

Панель на этом же Windows:

```bash
SKLAD_DRIVE_MODE=agents SKLAD_WINDOWS_AGENT_URL=http://127.0.0.1:4372 npm run dev
```

Адрес для панели на этой машине: `http://127.0.0.1:4372`. Если панель на Mac, а агент на ПК, в `SKLAD_WINDOWS_AGENT_URL` ставят `http://<IPv4 этого ПК>:4372`. Это порт полки, не `4730`.

Те же две команды с `--mock` — проверка без дисков. Это снова демо.

### Агент заданий Windows

Отдельный процесс: HandBrake, `compact.exe`, индекс NTFS и оптика. Это не агент полки. Скрипт в `package.json`: `npm run pc-agent` вызывает `node agents/pc-agent/server.mjs`. Порт — `PORT`, иначе `4730`. Адрес прослушивания — `SKLAD_PC_AGENT_HOST`, иначе `127.0.0.1`.

Макет здесь включён по умолчанию. `agents/pc-agent/server.mjs` считает `mock`, пока `SKLAD_PC_AGENT_MOCK` не равен строке `0`.

Настоящий запуск — на Windows, из корня репозитория, когда `HandBrakeCLI.exe` и `compact.exe` уже лежат по путям:

```bat
set SKLAD_PC_AGENT_MOCK=0
set SKLAD_PC_AGENT_HOST=0.0.0.0
node agents/pc-agent/server.mjs
```

Панель на той же машине использует `http://127.0.0.1:4730`. С Mac — `http://<IPv4 ПК>:4730` (свой адрес из `ipconfig`). Тот же URL задаётся в «Медиа и игры → Настройки» у хоста «Windows PC» и переменной `SKLAD_PC_AGENT_URL` (оптика и индекс). Пока в настройках медиа включён демо-режим, панель этот агент не вызывает. VLESS нет.

## Демо

В демо уже есть:

- готовый фильм на `/Volumes/vault/Cinema` — его можно перенести, раздача останется;
- `God of War (PSP)` в `/Volumes/vault/PSP/Games/Downloads` — часть файлов целая, часть нет, кнопка «Оставить только целые» снимает недокачанные с загрузки;
- раздачи Windows с путями `D:\Games`, `D:\Downloads` и `E:\Archive`.

Поиск смотрит имя, каталог и имя хоста. Например, `PSP` или `vault`.

## Web UI на Mac

1. Установите qBittorrent с [qbittorrent.org](https://www.qbittorrent.org/).
2. Откройте **qBittorrent → Настройки…** (⌘,), на английском это **Settings…** или **Preferences…**.
3. Раздел **Веб-интерфейс** / **Web UI**.
4. Включите **Веб-интерфейс (удалённое управление)** / **Web User Interface (Remote control)**.
5. IP: `*` если к Web UI будете ходить с другого компьютера, или `127.0.0.1` если Склад запущен на этом же Mac. Порт оставьте `8080`, если он свободен.
6. Задайте имя и пароль. Пустой пароль Склад не сохраняет.
7. Защиту от CSRF не выключайте. Склад сам отправляет `Referer` и `Origin`.
8. По желанию включите **Обход аутентификации для клиентов с localhost** — только когда и Склад, и qBittorrent на одной машине.
9. Нажмите **Применить** / **Save**.
10. Проверка на самом Mac: в браузере открывается `http://127.0.0.1:8080`, видна страница входа qBittorrent.

Если Склад на другом компьютере, в «Системных настройках → Сеть → Брандмауэр» разрешите входящие для qBittorrent.

## Web UI на Windows

1. **Инструменты → Настройки → Веб-интерфейс** / **Tools → Options → Web UI**.
2. Та же галочка удалённого управления, порт `8080`, свой логин и пароль.
3. В брандмауэре Windows разрешите qBittorrent в частной сети.
4. IP машины: в `cmd` команда `ipconfig`, строка IPv4. Например `192.168.1.50`.
5. С Mac mini откройте `http://192.168.1.50:8080` — должна быть страница входа qBittorrent.

## Оба компьютера в Складе

Кнопка **Хост**.

| | Mac mini | Windows-ПК |
| --- | --- | --- |
| Адрес | `http://127.0.0.1:8080`, если Склад на этом Mac | `http://192.168.1.50:8080` |
| Система | macOS | Windows |
| Каталоги | `/Volumes/vault/Downloads`, `/Volumes/vault/PSP/Games/Downloads` | `D:\Downloads`, `D:\Games` |

Нажмите **Проверить**, затем **Сохранить**. В карточке хоста появится версия qBittorrent. Поддерживаются и 4.x (`pause` / `resume`), и 5.x (WebAPI 2.11+, `stop` / `start`).

Если панель крутится не на Mac mini, укажите локальный IP Mac вместо `127.0.0.1`. Оба адреса должны открываться с той машины, где запущен `npm run dev`. Отдельный VPN или прокси не настраивается.

## Куда сохранять и как переносить

При добавлении магнет-ссылки или `.torrent` выбирается хост и каталог. Пресеты — это ваши диски, плюс можно вписать путь вручную. На macOS путь начинается с `/`, на Windows — с буквы диска, например `D:\Downloads`.

**Перенести** у раздачи вызывает `setLocation`: qBittorrent перемещает уже скачанное в другой каталог **на том же компьютере** и продолжает раздачу. Пока диск занят, состояние будет «Перемещение».

**Только отметить** ничего не двигает: раздача попадает в фильтр «К переносу», чтобы не забыть.

**Оставить только целые** ставит недокачанным файлам приоритет «не скачивать» (`filePrio` = 0). Файлы на 100% остаются. У каждого файла приоритет можно сменить отдельно: не скачивать, обычный, высокий, максимальный.

Удаление по умолчанию не трогает файлы на диске. Галочка «Также удалить файлы с диска» включает `deleteFiles`.

## Очередь

Перенос, копирование, индексация диска, сжатие NTFS и перекодирование HandBrake не выполняются внутри запроса страницы. Кнопка «Поставить в очередь» сразу записывает задачу и возвращается. Очередь лежит в `data/jobs.json` (файл в git не входит) и переживает перезапуск приложения и браузера.

Воркер Mac (`mac-local`) и воркер Windows (`pc-agent`) сами забирают свои задачи. Одну задачу нельзя взять дважды: переход «в очереди → выполняется» атомарный. Повтор той же операции — тот же источник, назначение, тип и компьютер — пока задача в очереди, выполняется или на паузе, не создаёт вторую запись.

Отмена не удаляет файлы. Исходник после переноса или копирования удаляется только отдельным подтверждением, когда результат уже проверен. В демо воркеры внутри процесса имитируют прогресс и не трогают диск, HandBrake и compact.exe. Страница «Очередь» получает прогресс по SSE; если поток обрывается, остаётся редкий опрос.

## Правила раскладки

Страница [Правила](http://127.0.0.1:4317/policies) угадывает тип раздачи: игра (ПК, консоль, PSP или другое), фильм, сериал, музыка, софт, документы или другое. Сначала ручная пометка, потом расширения файлов, потом имя. Большой файл сам по себе не считается игрой.

У каждого типа есть диск, папка, индексация (нет / обычный обход / NTFS MFT) и действие после загрузки (нет / CompactGUI / HandBrake). Пресеты «Полка: игры на HDD, кино на медиадиск» и «Всё только индексировать» только подставляют правила и сами автоматику не включают.

Автоматика по умолчанию выключена. Перед включением нужен сухой прогон: тип, диск, папка, индекс и обработка. Смена правил делает прогон устаревшим, включить нельзя, пока его не повторят.

Исходники молча не удаляются. HandBrake и сжатие ставят отдельное задание с новым путём; удаление источника — отдельное подтверждение, оно не входит во включение автоматики. Перенос готовой раздачи идёт через `setLocation` в qBittorrent, чтобы раздача продолжалась. CompactGUI предлагается только на NTFS, не на APFS.

## Где пароли

Логин и пароль Web UI лежат в `data/hosts.json` на машине, где запущен Склад. Файл в git не попадает. В браузер пароль обратно не отдаётся. У приложения нет своей авторизации: не публикуйте порт 4317 в интернет. Домашней сети достаточно.

Демо-хосты в этот файл не записываются, их нельзя удалить, только сбросить раздачи из меню хоста.

## Полка дисков

Полка помнит физические диски, которые большую часть времени лежат отдельно и не подключены. Запись не привязана к букве диска и не к точке монтирования. Ключ — серийный номер и UUID тома плюс файловая система. Тот же диск в другом порту SATA или USB, с `E:` вместо `D:` или с `/Volumes/vault 1` вместо `/Volumes/vault`, остаётся одной карточкой. Клон с тем же UUID и другим серийным номером — отдельный диск, полка помечает его как возможную копию и не сливает записи. Две точки монтирования одного серийного номера и UUID на одном компьютере — тоже один диск.

В каталоге, файл `data/drives.json` (в git не входит, рядом лежит `data/.gitkeep`):

- своё имя диска, его можно поменять;
- объём и свободно на момент последнего удачного просмотра;
- дерево файлов и папок без содержимого файлов;
- пометки торрент / игра / медиа, если путь совпадает с известным каталогом библиотеки или рядом лежит `sklad-catalog.json`;
- когда диск видели и на каком компьютере: Mac mini или Windows.

Страница [http://127.0.0.1:4317/drives](http://127.0.0.1:4317/drives) («Полка дисков») открывается из шапки, отдельно от таблицы раздач. Поиск идёт по всем дискам, включая те, что на полке. Если файл нашёлся на отключённом диске, полка пишет, какой диск подключить, например «Подключите диск «Архив 2019»», и не делает вид, что файл сейчас открывается.

Пока Склад запущен здесь, включён демо-режим: синтетические диски, часть подключена, «Архив 2019» лежит на полке. Железо для этого не нужно. Повторное подключение Vault с тем же серийным номером и UUID не создаёт вторую карточку, даже если путь стал `/Volumes/vault 1`.

Настоящие машины: панель опрашивает URL агентов. Облако само диски не видит.

Команды настоящего Mac и Windows, порты `4371` и `4372`, и то, чем панель их включает, — в разделе «Настоящие агенты хостов» выше. Кратко, из корня репозитория и без `--mock`:

```bash
node --import ./agents/register.mjs agents/mac-agent/drive.mts --port 4371
node --import ./agents/register.mjs agents/pc-agent/drive.mts --port 4372
```

Проверка без дисков: те же команды с `--mock`.

Адреса можно положить в `data/drive-agents.json` и выставить `"mode": "agents"`, либо задать `SKLAD_DRIVE_MODE=agents`, `SKLAD_MAC_AGENT_URL` и `SKLAD_WINDOWS_AGENT_URL`. Пока режима `agents` нет, Склад остаётся в демо.

На Windows быстрый индекс NTFS читает MFT и журнал USN, как Everything. Для этого агент нужен от имени администратора: сырой том открывается только так. Без прав администратора полка прямо говорит, что идёт обычный обход папок. Журнал USN только читается.

APFS, HFS, exFAT и каталоги на Mac вроде `/Volumes/vault` всегда обходятся как обычные папки. MFT на APFS не используется.

Индексация только читает. Она не форматирует, не инициализирует, не чинит, не меняет буквы, не уплотняет, не сжимает, не переносит и не удаляет файлы. Если диск занят, индекс встаёт на паузу и потом продолжается. Ошибка просмотра не вычёркивает уже найденные файлы: они пропадают из каталога только после полного удачного просмотра, в котором их больше нет. Перенос и уплотнение остаются отдельными действиями в разделе медиа и игр, приезд диска их не запускает.

## Одна загрузка на физический диск

На одном физическом диске одновременно качается только одна раздача. Диски независимы: Vault и диск D могут качать одновременно, каждый — свою раздачу. Остальные раздачи на тот же диск ждут в очереди и стартуют сами, когда текущая доходит до 100% или выходит из загрузки, метаданных, простоя без пиров или проверки в раздачу.

Раздача уже скачанного не ограничена. Сиды и раздачи на паузе слот не занимают.

Если диск отключён — в каталоге дисков он офлайн — очередь этого диска ждёт. На отсутствующий диск загрузка не стартует. В интерфейсе это «Диск «Архив» не подключён».

Какой это диск: сначала каталог Склада, серийный номер и UUID. Два хоста qBittorrent с одной и той же парой делят один слот, даже если путь на Mac выглядит как `/Volumes/…`, а на Windows — как `D:\…`. Если пути в каталоге нет, берётся запасной ключ из хоста и тома: macOS `/Volumes/<имя>` или `/` для системного диска, Windows — буква диска. Запасной ключ описан в `src/lib/scheduler/disk-key.ts`. Такой диск считается подключённым: о нём никто не сообщил, что его нет.

Очередь видна на страницах «Прогресс» и «Очередь». Порядок и пометка «следующим» выбирают, какая ожидающая раздача стартует, и не открывают вторую загрузку на том же диске.

## Медиа и игры

Отдельный раздел: [http://127.0.0.1:4317/tools](http://127.0.0.1:4317/tools). Там очередь HandBrake, перенос папки игры с проверкой и сжатие NTFS на Windows. В таблицу раздач это не встроено. Если раздача скачана целиком, в карточке есть ссылки «В HandBrake» и «Перенести или сжать папку»: путь и система хоста подставляются в мастер.

Настройки путей (HandBrakeCLI, compact.exe, каталоги, адрес агента) и сами задания лежат в `data/` рядом с хостами qBittorrent и в git не попадают. Пока включён демо-режим, интерфейс показывает очередь и команды, но ничего не запускает. Так раздел работает и на машине, где HandBrake не установлен.

### HandBrake на Mac

1. Скачайте HandBrake с [handbrake.fr](https://handbrake.fr/) и при установке оставьте инструмент командной строки, либо выполните `brew install handbrake`.
2. В терминале: `HandBrakeCLI --version`.
3. Типичные пути: `/usr/local/bin/HandBrakeCLI` и `/opt/homebrew/bin/HandBrakeCLI`.
4. В Складе: **Медиа и игры → Настройки**, поле HandBrakeCLI у «Mac mini». Если бинарник нашёлся, страница очереди это пишет.

Склад не кладёт HandBrake внутрь себя.

### HandBrake на Windows

1. Установите HandBrake с того же сайта. Нужен `HandBrakeCLI.exe`, обычно `C:\Program Files\HandBrake\HandBrakeCLI.exe`.
2. В `cmd`: `"C:\Program Files\HandBrake\HandBrakeCLI.exe" --version`.
3. Flatpak (`flatpak run --command=HandBrakeCLI fr.handbrake.ghb`) — вариант для Linux, не для Windows. На ПК укажите exe вручную, если путь другой. Второе поле в настройках как раз для запасного exe.
4. Этот путь задаётся у хоста «Windows PC». Само кодирование на ПК делает агент ниже, а не процесс Склада на Mac.

Пресеты в форме — подписи к встроенным пресетам HandBrake: «Быстрый 1080p» (`Fast 1080p30`), «Совместимый» (`Very Fast 1080p30`), «Высокое качество».

### CompactGUI и compact.exe

1. CompactGUI можно поставить на Windows как наглядное окно: [github.com/IridiumIO/CompactGUI](https://github.com/IridiumIO/CompactGUI). Склад его не вызывает.
2. Сжатие идёт системной командой, она уже есть в Windows: `compact.exe /C /EXE:LZX` (также XPRESS16K, XPRESS8K, XPRESS4K) для выбранной папки.
3. Это только NTFS: буква диска (`D:\Games\Control`) или UNC (`\\server\share\Games`).
4. На Mac кнопка недоступна, подпись «Только Windows, NTFS». Каталог vault (`/Volumes/vault`, APFS) так сжимать нельзя, и Склад такой путь отклоняет.

Оценка «было / стало» в очереди появляется, когда её вернул демо-режим или агент. В этом облаке это оценка демо, диск не меняется.

### Агент на Windows

Склад часто крутится на Mac. Задания для ПК принимает маленькая программа без своих бинарников HandBrake:

```bash
node agents/pc-agent/server.mjs
```

Подробности — в `agents/pc-agent/README.md`. Кратко: по умолчанию агент слушает `127.0.0.1:4730` и работает в макете (прогресс и команды, без запуска программ). Чтобы с Mac было видно ПК, на Windows задайте `SKLAD_PC_AGENT_HOST=0.0.0.0`, откройте порт `4730` в частной сети и в настройках Склада укажите `http://192.168.1.50:4730`.

Задания Mac выполняются на той машине, где запущен `npm run dev`. Отдельный VLESS или прокси не настраивается.

Настоящий запуск на ПК — только с `SKLAD_PC_AGENT_MOCK=0`, когда `HandBrakeCLI.exe` и `compact.exe` уже лежат по указанным путям.

### Перенос папки

Мастер спрашивает источник и назначение. На ПК это разные буквы, например `D:\Games\Control` → `C:\Games\Control`. На Mac — внутренний каталог и внешний том, например `/Users/me/Games/Title` → `/Volumes/vault/Games/Title`.

Дальше копия и проверка: число файлов, суммарный объём и хеш списка файлов. Исходная папка остаётся. Удаление — отдельная кнопка в очереди, и только если проверка сошлась и вы её подтвердили. Если проверка не сошлась, удалить источник нельзя. На NTFS после проверки можно перейти к сжатию папки назначения. Новое место пишется в библиотеку раздела.

## Рисунок на поверхности диска

Раздел «Оптика» в том же Складе ставит в очередь рисунок на CD, DVD и однослойном BD-R через отдельно установленный [DiscImageStudio](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio) (JiaFeiMiao-K-Cat). Лицензия upstream — [GPL-3.0-or-later](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/blob/main/LICENSE). Исходники и бинарник DiscImageStudio в этот репозиторий не входят и не перелицензируются: пользователь ставит официальную сборку со [страницы релизов](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/releases).

Привязка к документации v1.4.2. Офлайн-сборка, macOS, Linux и Windows:

- CD: `disc-image-studio cd-generate --input КАРТИНКА --output ФАЙЛ.wav --sectors 359849`. С папкой файлов добавляется `--data-dir` и выходной ISO.
- DVD, один слой, пресет `dvd-5-120mm`: `disc-image-studio solve --image КАРТИНКА --iso-output ФАЙЛ.iso --total-sectors 2295104 --fill-sectors 2295104`.
- BD-R 25 ГБ: `disc-image-studio bd-generate --input КАРТИНКА --output ФАЙЛ.iso --preset bd-r-sl-25gb --total-sectors 12219392`.

Двухслойный BD и DVD-DL для этой функции отклоняются до очереди: upstream описывает однослойный BD-R и однослойные пресеты DVD-5.

Рекордер DVD стоит на Windows-ПК. Mac — пульт: он ставит фоновое задание и показывает прогресс, в том числе имя привода, которое сообщил агент. Локальный DVD-привод на Mac не ищется и не заявляется. Адрес агента — обычный HTTP в домашней сети (`SKLAD_PC_AGENT_URL` или настройка в разделе оптики), без VLESS. Если агент выключен, задание остаётся в очереди с ошибкой «агент Windows недоступен». Запасной записи через `drutil` или `hdiutil` нет.

Обнаружение DVD±R/RW, живая запись и проверка после успешного завершения процесса записи выполняются только воркером Windows (`host: pc-agent`). Перезаписываемый диск сам не стирается: явное подтверждение хранится на задании и выполняется агентом Windows.

Windows: живая запись DiscImageStudio идёт через IMAPI2 и в документации названа экспериментальной. Очередь живой записи — только агент Windows. У опубликованного CLI нет флага, который пишет диск. Кнопка «Записать на Windows» ставит в эту очередь команду `burn-devices`: она перечисляет приводы IMAPI2 и не прожигает носитель. Склад сам лазер не включает и не утверждает, что диск записан в этой среде.

macOS и Linux: экспериментальный CLI — необязательная офлайн-генерация образа, привод не нужен. Это не живая запись. Последующая запись такого образа снова задание агента Windows.

Если бинарник не найден, задача переходит в ошибку «DiscImageStudio не найден» и даёт ссылку на релизы, а не в «готово». Очередь общая, страница «Прогресс». VLESS не используется. В этом облачном окружении диск не записывался и видимый рисунок на болванке не проверялся.

## Индекс файлов NTFS (MFT)

Раздел **Медиа и игры → Индекс** (`/tools/index`) показывает, где лежит игра: хост, полный путь и способ ответа — `MFT`, `USN` или `обход папок`. Мастер **Перенос игры** ищет ту же базу и подставляет выбранную папку в поле источника. Исходная папка по-прежнему не удаляется, пока копия не проверена и удаление не подтверждено в очереди.

Индекс MFT на Windows — это чтение главной файловой таблицы NTFS (Master File Table) и журнала USN, тот же принцип, что у Everything. Агенту нужны права администратора, потому что он открывает сырой том (`\\.\D:`) и вызывает `FSCTL_ENUM_USN_DATA` / `FSCTL_READ_USN_JOURNAL`. С этой облачной машины чужой диск не читается: парсер проверяется на синтетических записях.

Если агент запущен обычным пользователем, индекс MFT недоступен. Остаётся обычный обход папок: медленнее и без сырого диска. В карточке тома это прямо написано, а у каждой строки бейдж «обход папок».

APFS на Mac и любой путь `/Volumes/vault` (и вообще `/Volumes/…`) никогда не идут через MFT. Там только обход папок, даже если процесс повышен.

### Как запустить агент ПК

Из каталога Склада, Node.js 22:

```bash
npm run pc-agent
```

То же самое: `node agents/pc-agent/server.mjs`. Агент слушает `127.0.0.1:4730`. Проверка индекса: `http://127.0.0.1:4730/v1/index/health`.

Обычный запуск (окно без «Запуск от имени администратора», а также Mac и Linux, где крутится демо): `elevated: false`. Том NTFS индексируется обходом папок, MFT не открывается.

Запуск от администратора на Windows, чтобы включить MFT и USN:

1. Откройте `cmd` или PowerShell через «Запуск от имени администратора».
2. Перейдите в каталог Склада.
3. Выполните `npm run pc-agent`.
4. Первое построение тома NTFS читает MFT. Следующее обновление того же тома читает журнал USN и не обходит весь диск заново.

Панель для томов Windows спрашивает этот агент. Каталоги Mac, включая `/Volumes/vault`, панель обходит сама и не шлёт их в код MFT/USN.

## LocalSend

Склад умеет сам быть участником LocalSend в локальной сети. Отдельное приложение не нужно. Протокол — [LocalSend protocol v2](https://github.com/localsend/protocol): UDP multicast `224.0.0.167:53317` и HTTPS на порту `53317`.

Страница [http://127.0.0.1:4317/localsend](http://127.0.0.1:4317/localsend). Отправка выбранных файлов с полки или из списка на этой машине ставит фоновую задачу и сразу возвращается. Прогресс — на общей странице «Прогресс»: очередь, передача, пауза, готово, ошибка, байты, скорость, ETA и текущий файл. Готово появляется только после HTTP 200 на `prepare-upload` и на каждый `upload`. Отказ получателя, обрыв или молчащий демо-сервер — это ошибка, не «отправлено».

Повтор тех же файлов тому же устройству, пока задача ещё идёт, возвращает ту же задачу.

### Mac и Windows

1. Установите LocalSend с [localsend.org](https://localsend.org/) **или** откройте Склад на той же машине: он сам слушает порт `53317`.
2. Оба компьютера в одной домашней сети. VLESS, VPN и прокси не нужны и не настраиваются.
3. В брандмауэре разрешите входящие TCP и UDP `53317` в частной сети.
4. Если мультикаст не проходит, на странице LocalSend добавьте устройство по IP.
5. Сверьте отпечаток. Для HTTPS это SHA-256 сертификата. Если сертификат на том же адресе сменился, Склад останавливает отправку и не подменяет устройство молча.
6. Папка приёма задаётся в настройках на этой странице: диск с полки и относительная папка либо абсолютный путь. На Mac путь APFS (`/Volumes/vault/Incoming`), на Windows NTFS (`D:\Incoming`). Путь Mac не записывается как NTFS.
7. Когда upload по протоколу реально завершился, файл попадает в индекс полки (добавление, без формата и переноса) и проходит сухой прогон правил. Ничего само не удаляется.

### Демо в облаке

Настоящий Mac или ПК отсюда недоступен. Для разработки:

```bash
LOCALSEND_MOCK=1 npm run dev
```

Склад поднимает в процессе mock-сервер и показывает его как «Демо LocalSend». Клиент ходит в него тем же протоколом. Если сервер не запущен, устройство пропадает, а задача становится ошибкой. Это не успешная отправка на компьютер в сети.

## Диски DVD

Страница [Диски DVD](http://127.0.0.1:4317/optical) берёт файлы из каталога Drive Manager (подписи дисков и проиндексированные пути). Если каталога ещё нет, подставляются записи той же формы: подпись диска, путь, размер. Перед постановкой в очередь размер сравнивается с профилем. CD считается по 700 МиБ (650 МиБ — старый номинал, в проверку не входит). DVD±R/RW — 4 700 372 992 байт. DVD±R DL — 8 543 666 176 байт. Если дерево больше, задача не создаётся.

Запись и сборка ISO — обычные фоновые задачи. Ответ приходит сразу, прогресс виден на странице «Прогресс»: очередь, выполнение, пауза, готово, ошибка, процент, текущий файл и фаза «образ», «запись» или «проверка». Проверка начинается только после нулевого кода записи. Повтор того же набора файлов, того же привода и того же типа, пока задача активна, отклоняется.

Перезаписываемый диск (DVD-RW, DVD+RW, CD-RW) сам не стирается. Кнопка «Стереть» выключена, пока не отмечено подтверждение или не введена подпись диска. Флаг стирания попадает в команду только если это подтверждение записано в задачу.

После успешной проверки диск попадает на полку: подпись, UUID (новый, если у болванки нет читаемого идентификатора; серийный номер оборудования не выдумывается), дерево файлов, место («полка, коробка 2») и источник `source: mock` или `source: tool`. Поиск говорит, какую подпись достать, даже если диска нет в приводе.

### macOS

Утилиты уже в системе, отдельно ставить не нужно:

- приводы: `drutil status`, `drutil list`, `diskutil info <device>`
- образ: `hdiutil makehybrid -o <файл.iso> -iso -joliet <папка>`
- запись без проверки внутри той же команды: `hdiutil burn -device <device> -noverifyburn -noeject <файл.iso>`
- стирание только после подтверждения: к `hdiutil burn` добавляется `-erase` (короткое стирание DVD-RW/CD-RW, затем запись). Отдельная кнопка: `drutil -drive <номер> erase full`
- проверка после кода 0: `hdiutil checksum -type SHA256 <файл.iso>` и `drutil status`

### Windows

Nero и другие проприетарные рекордеры не входят в поставку.

- приводы: PowerShell `Get-CimInstance -ClassName Win32_CDROMDrive` и IMAPI2 (`IMAPI2.MsftDiscMaster2`, `IMAPI2.MsftDiscFormat2Data`) в `scripts/optical/imapi-detect.ps1`. Если PowerShell недоступен: `wmic cdrom get DeviceID,Name,Drive,MediaLoaded,MediaType,Caption,PNPDeviceID /format:list`
- образ: `oscdimg -n -m -l<МЕТКА> <папка> <файл.iso>` из Windows ADK. Если `oscdimg` нет, задача падает с «Утилита не найдена», а не пишет, что диск готов
- запись: `powershell.exe -NoProfile -NonInteractive -File scripts/optical/imapi-burn.ps1` (IMAPI2FS). По умолчанию `-Erase:$false`. Стирание только с `-Erase`
- проверка: `scripts/optical/imapi-verify.ps1` считает `Get-FileHash -Algorithm SHA256` у собранного ISO

### Это облако

Здесь нет оптического привода. Детектор отвечает «привод не найден» и ничего не запускает. Демо (`SKLAD_OPTICAL_DEMO=1` или переключатель на странице) подставляет ложные приводы и имитирует коды выхода. Такая задача помечена `mock: true`, на полке у неё `source: mock`. Это не успешная запись на оборудование. В этой среде физический диск не записывался.

## SHA-256

Подсчёт хэша — отдельная фоновая задача. Кнопка или завершение раздачи только ставит её в очередь и сразу возвращается. Внутри HTTP-запроса файлы не читаются, окно не ждёт. Прогресс на общей странице «Прогресс»: текущий файл, сколько файлов готово, байты, процент, скорость и оценка времени. Записи лежат в `data/integrity.json` (в git не входит): относительный путь, размер, SHA-256 в нижнем регистре, статус (`pending`, `hashing`, `match`, `mismatch`, `error`, `recorded`), сколько байт уже прочитано и время обновления. Общий модуль — `src/lib/integrity`. После перезапуска продолжается со следующего ещё не посчитанного файла. Отмена останавливает воркер, уже записанные хэши оставляет и ничего не удаляет.

Сравниваются байты, и только после полного совпадения и отдельного подтверждения можно включить «удалить исходные файлы»:

- перенос и копирование HDD → SSD: тот же относительный путь, тот же размер, тот же SHA-256 у источника и копии;
- LocalSend: хэш каталога до отправки и хэш принятых байт после того, как передача реально завершилась. Пока задача передачи не готова, статус `match` не ставится;
- CompactGUI / `compact.exe` на NTFS: логические байты до и после. Сжатие их не меняет, читается файл через обычное API, а не размер кластера. Отличие — ошибка целостности, не успешное сжатие;
- запись на оптический диск (агент Windows, Mac только ставит задачу): после записи файлы читаются с диска или из подставного читателя и сравниваются с источником. Совпавшие суммы попадают в каталог проверенного диска. Несовпадение проверку проваливает и запись «проверено» не добавляет. Перезаписываемый диск сам не стирается.

Только записываются, без сравнения:

- готовая раздача: SHA-256 каждого файла в каталоге сохранения. Кнопка копирует манифест `<имя>.sha256` в виде `sha256sum`: `<hex>  <относительный-путь>` (два пробела). Это копия уже посчитанных сумм. Если их нет, ставится та же фоновая задача, а не новый блокирующий подсчёт;
- HandBrake: отдельно «хэш входа» и «хэш выхода». Перекодирование меняет байты, равенство не проверяется и удаление исходника не открывает.

Несовпадение или ошибка показывает, какой файл отличается, и оставляет удаление выключенным. Само по себе совпадение хэшей тоже ничего не стирает.
